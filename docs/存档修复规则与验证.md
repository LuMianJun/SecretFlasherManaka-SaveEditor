# 存档修复首版

修复功能使用 `tauri/repair_profile.json` 内置规则，运行时不读取 Unity 工程、游戏文件、BepInEx 或任何 MOD DLL。当前规则来自已核查原版资源与恢复代码，包含 107 个 GameStateData 字段、66 个角色外观字段、188 个原版服饰部件，以及任务、物品、枚举和预设结构。规则文件记录来源代码的 SHA256，用于后续核对更新，不代表支持所有游戏版本。

## 执行与保存

`preview_repair` 只生成清单和当前内容哈希。`apply_repair` 再检查哈希，重新计算修复，整批提交为一个撤销步骤，不落盘。已有合法标量沿用源文本，避免浮点转换丢失精度。普通编辑和保存不触发清理。

应用修复后，后端禁止覆盖该次修复的源文件，前端的“保存”自动转为另存为。保存仍通过原有加密、临时写入、目标变更和槽位校验流程。修复的是进度文件；正常保存到手动槽位时，既有系统槽位摘要同步行为仍然保留。

## 清理与补全范围

- 移除进度文件非原版顶层键、GameStateData 与已核查嵌套对象中的扩展字段。
- 按原版枚举和主表编号清理字典键、枚举值和编号列表；原版旧编号及哨兵值会保留。技能和物品等不能只根据 UI 名称表判断编号有效性。
- 同步清理服饰所有权/装备、选项、强化、锁定和每个服装预设的部件列表及选项引用。
- 清理自定义任务等扩展进度。该模式面向恢复原版兼容，使用者必须在预览中确认会损失的 MOD 数据。
- 缺失/无效结构按内置默认规则补齐，包含 3 个强化效果槽、4 个锁定开关、20 个服装和外观预设、原版技能初始记录与原版服饰强化/锁定记录。
- 只补回可确定的默认值，不重建丢失的真实任务成绩、购买历史或自定义外观。部分缺失发型记录仍由原版 LoadGameState 按资源默认值补齐，工具仅提供已核实的初始短发兜底。

## 故障样本

提供两种合成样本，使用游戏的加密格式：

1. `cosplay-residue.sd`：以原版默认结构为底，按所提供 Cosplay Loader 2.2.1 的编号追加行为加入 `10033`。该 ID 出现在所有权/装备、选项、强化、锁定、服装预设部件和预设选项六个引用位置。原版上身部件到 `10032`，移除扩展后这些引用无法由原版主表解析。
2. `cosplay-and-missing-data.sd`：在上述残留上删除原版技能字典、删除 `20011` 的强化记录、缩短锁定数组，并加入扩展任务和额外顶层数据，覆盖“清理＋补全”。

相应 `*-repaired.sd` 是修复引擎生成的对照文件。样本来自测试构造，不是实际游玩保存后复现的坏档；其中默认进度不能用于替代真实游戏进度。

测试样本可用 Rust 测试再生成，输出目录必须是新目录：

```powershell
cd tauri/src-tauri
$env:SAVE_REPAIR_FIXTURES_DIR = 'D:/a-new-disposable-fixture-directory'
cargo test export_cosplay_fault_fixture_when_requested
Remove-Item Env:SAVE_REPAIR_FIXTURES_DIR
```

原生窗口检查使用 `tauri/check-native-repair.mjs`，依次传入 EXE、上述样本目录、一个新的结果目录；可再传入现有进度副本进行保留检查。它只写测试结果目录，通过 WebView2 检查预览、取消、应用、撤销、原文件保护、另存、重新读取和第二次扫描。

## 边界

首版只接收可解密、可解析且具有原版 GameStateData 类型头的进度文件。缺失或异常的槽位 ID 可在修复时按 `0.sd`～`19.sd` 文件名补齐，其他名称使用原版未分配值 `-1`。

系统存档、文件截断、错误密码/加密、缺失整个类型头、无法识别的新版本或任意组合的游戏逻辑错误不在首版恢复保证内。编号仍合法但已对应不同 MOD 衣服的历史错配，无法从数字本身还原其原始含义。

加密与结构验证、原版编号引用验证和原生编辑器窗口检查，与游戏内实际读档是不同层级。

## 2026-10-26 游戏内对照验证

用户在同一游戏安装中验证：Cosplay Loader 启用时，服饰残留构造样本可以运行；退出游戏并将插件 DLL 移出加载目录后，读取第 3 槽 `2.sd` 出现故障，日志确认 Cosplay Loader 未加载，并产生连续空引用异常。具体首个失败调用点尚未定位，不能把后续空引用堆栈当作已定位的根因。

使用本修复引擎对该槽应用 14 项修复，另存为第 4 槽 `3.sd`，保留原故障槽。用户随后确认修复副本可以正常运行。准备副本时已验证：原 `0.sd`、`1.sd`、`2.sd` 不变，仅同步系统存档中第 4 槽的列表摘要；修复副本重新打开和再次扫描通过。

该结果验证了这个已在游戏中复现的合成服饰残留案例，不代表所有 MOD 坏档、自然游玩生成的坏档或其他游戏版本均可恢复。
